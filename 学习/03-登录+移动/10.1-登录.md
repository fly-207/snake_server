### (login) function C2GSLoginRole(oConn, mData)

简单判断了当前服务的状态(维护/未开启/白名单等)

如果未通过, 则返回包含错误的消息; 通过则进入到下一步


### (login) function CConnection:LoginRole(mData)

因为会以异步方式查询数据库, 所以可能在查询未返回过程中, 发送第二次登陆消息, 这里使用状态 `iStatus` 的方式过滤

    if iStatus ~= gamedefines.LOGIN_CONNECTION_STATUS.login_account then
        oGateMgr:KickConnection(self.m_iHandle)
        return
    end
    self.m_oStatus:Set(gamedefines.LOGIN_CONNECTION_STATUS.in_login_role)

随后查询数据库, 并将结果返回后注入到回调函数形参中

    gamedb.LoadGameDb(self.m_sServerTag, "login", "common", "DbOperate", mInfo, function (mRecord, mData)
        local oConn = global.oGateMgr:GetConnection(iHandle)
        if oConn then
            oConn:_LoginRole1(mRecord, mData)
        end
    end)

### (login) function CConnection:_LoginRole1(mRecord, mData)

先进行 `账号`/`渠道`/`删号`/`封号`一系列过滤, 随后进入到是否登陆排队判断

这里有个奇怪分支

    local oLoginQueueMgr = global.oLoginQueueMgr
    if not oLoginQueueMgr:ValidLogin(pid, self.m_iHandle) then
        self:OnStartLoginQueue(pid)
        return
    end

在上面的代码中, 如果进入到 `if` 语句中后, 接下来的登录流程似乎缺少正常进入游戏的逻辑

    # 数据被记录到 CLoginQueueMgr 中后, 没有调用 CGateMgr:Send2WorldLogin 交互的逻辑

假设不进入到 `if` 分支, 则进入到 `CGateMgr` 的队列中

### (world) CWorldMgr:_Login(mRecord, mConn, mRole)

接管 `socket` 消息, 这样网关服务转发的消息会被 `world` 服务处理, 处理逻辑在 `world/netcmd` 中
