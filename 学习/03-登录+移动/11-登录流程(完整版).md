## 1. 整体架构说明

游戏服务端由多个 skynet 服务协同工作：

| 服务名     | 职责                                                      |
| --------- | --------------------------------------------------------- |
| `login`   | 接受客户端连接，处理账号/角色登录验证，管理登录排队         |
| `world`   | 玩家对象的生命周期管理；接管 socket 后处理玩家逻辑          |
| `scene`   | 独立的场景进程（多个），负责 AOI 计算和位置同步             |
| `gamedb`  | 异步数据库代理                                            |

客户端与 `login` 服务的 `zinc_gate`（C 网关）建立 TCP 连接。角色登录成功后，`world` 服务通过 `oConnection:Forward()` **接管该 socket**，后续消息由 `world` 的 `netcmd/` 处理。

### 3.2 `CConnection:LoginRole(mData)`

文件：`service/login/CConnection.lua`  第 736 行

```lua
function CConnection:LoginRole(mData)
    local iStatus = self.m_oStatus:Get()
    -- 防止重复登录：状态必须是 login_account 才能继续
    if iStatus ~= gamedefines.LOGIN_CONNECTION_STATUS.login_account then
        oGateMgr:KickConnection(self.m_iHandle)
        return
    end
    self.m_oStatus:Set(gamedefines.LOGIN_CONNECTION_STATUS.in_login_role)

    -- 异步查询数据库，回调 _LoginRole1
    gamedb.LoadGameDb(self.m_sServerTag, "login", "common", "DbOperate",
        {module="playerdb", cmd="GetPlayer", cond={pid=pid}},
        function(mRecord, mData)
            oConn:_LoginRole1(mRecord, mData)
        end
    )
end
```

**关键点**：`iStatus` 防止同一连接在 DB 回调返回之前再次触发登录逻辑。

## 4. 登录排队机制

文件：`service/login/CGateMgr.lua`

```lua
LOGIN_QUEUE_LIMIT = 100   -- 同时允许进入 world 登录流程的上限
WAIT_PUSH_NUM     = 5     -- 每次定时器推送的数量（从等待队列移入登录队列）
```

```lua
function CGateMgr:EnterLoginQueue(iPid, mData)
    if self.m_iLoginCnt < LOGIN_QUEUE_LIMIT then
        self:Send2WorldLogin(iPid, mData)  -- 直接发往 world
    else
        self:EnterWaitQueue(iPid, mData)   -- 放入等待队列
    end
end
```

定时器（每 1000ms）执行 `CheckPushWaitQueue`，将最多 `WAIT_PUSH_NUM` 个等待玩家推入登录流程。

### 6.2 `CWorldMgr:_Login` — 核心登录逻辑

文件：`service/world/worldobj.lua`  第 431 行

```lua
function CWorldMgr:_Login(mRecord, mConn, mRole)
    local pid = mRole.pid

    -- 防止同一 pid 重复进入登录流程
    if self.m_mLoginPlayers[pid] then
        interactive.Send(mRecord.source, "login", "LoginResult",
            {pid=pid, handle=mConn.handle, token=mRole.role_token,
             errcode=gamedefines.ERRCODE.in_login})
        return
    end

    -- ① 接管 socket：此后客户端消息由 world 服务的 netcmd/ 处理
    local oConnection = connectionobj.NewConnection(mConn, pid)
    self.m_mConnections[mConn.handle] = oConnection
    oConnection:Forward()

    local oPlayer = self.m_mOnlinePlayers[pid]
    if oPlayer then
        -- ② 重复登录（如断线重连）：复用已有对象
        oPlayer:ReInitRoleInfo(mConn, mRole)
        oPlayer:OnLogin(true)   -- bReEnter = true
        interactive.Send(mRecord.source, "login", "LoginResult", {errcode=ok})
    else
        -- ③ 首次登录：创建 CPlayer 对象，放入 m_mLoginPlayers（登录中）
        local oPlayer = self:CreatePlayer(mConn, mRole)
        self.m_mLoginPlayers[pid] = oPlayer
        -- 第一步异步加载：基础玩家信息
        gamedb.LoadGameDb(..., "GetPlayer", ..., function(...)
            self:_LoginRole1(mRecord, mData)
        end)
    end
end
```

**`m_mLoginPlayers`** 和 **`m_mOnlinePlayers`** 是两个独立的表：
- `m_mLoginPlayers`：正在加载数据中的玩家
- `m_mOnlinePlayers`：已完全加载、在线的玩家

## 8. LoadEnd — 所有数据加载完成

文件：`service/world/worldobj.lua`  第 608 行

```lua
function CWorldMgr:LoadEnd(pid)
    local oPlayer = self.m_mLoginPlayers[pid]

    -- 将玩家从"登录中"移动到"在线"
    self.m_mLoginPlayers[pid] = nil
    self.m_mOnlinePlayers[pid] = oPlayer

    oPlayer:OnLoaded()    -- 数据全部加载完毕的回调
    oPlayer:OnLogin(false) -- bReEnter = false，首次进入游戏世界

    -- 通知 login 服务，登录成功
    interactive.Send(".login", "login", "LoginResult",
        {pid=pid, handle=..., token=..., errcode=gamedefines.ERRCODE.ok})
end
```

## 9. OnLogin — 玩家进入游戏世界

文件：`service/world/playerobj.lua`  第 933 行

`CPlayer:OnLogin(bReEnter)` 是登录流程中最复杂的一步，按顺序执行：

```
1. 写登录日志（IP、设备、平台等）
2. PreCheck()             — 首次登录时做数据校验/修复
3. PreLogin(bReEnter)     — 同步部分数据
4. CalApply()             — 重算物品/技能/神器/翅膀属性
5. 各离线对象的 OnLogin   — Profile / Friend / Privacy / WanfaCtrl / JJC
6. GS2CLoginRole()        — 向客户端推送角色基础信息
7. oWorldMgr:OnLogin()    — 通知世界管理器
8. oSceneMgr:OnLogin()    — ★ 通知场景管理器，玩家进入场景（见第 10 节）
9. 各控制器的 OnLogin     — Item / Skill / Task / Base / Active / Summon / ...
10. 全局管理器的 OnLogin  — Team / Mail / Friend / SysOpen / Rank / ...
11. 首次登录特殊处理      — 补充离线储备经验、处理未处理订单、合服逻辑等
```

**`GS2CLoginRole` 消息**在第 6 步发出，客户端收到该消息后知道角色已正式登录，开始显示游戏界面。

## 10. 进入场景

`oSceneMgr:OnLogin(oPlayer, bReEnter)` 判断如何进入场景：

```lua
function CSceneMgr:OnLogin(oPlayer, bReEnter)
    if bReEnter then
        self:ReEnterScene(oPlayer)    -- 断线重连：回到原场景
    else
        self:EnterDurableScene(oPlayer) -- 首次：进入持久化场景
    end
end
```

### 10.1 `EnterDurableScene` — 进入持久化场景

```lua
function CSceneMgr:EnterDurableScene(oPlayer)
    -- 从 ActiveCtrl 读取记录的上次场景/坐标
    local mDurableInfo = oPlayer.m_oActiveCtrl:GetDurableSceneInfo()
    local iMapId = mDurableInfo.map_id
    local mPos   = mDurableInfo.pos

    -- 选择负载合适的 scene 实例
    local oScene = self:SelectDurableScene(iMapId)

    -- 发起进入
    self:EnterScene(oPlayer, oScene:GetSceneId(), {pos = mPos})
end
```

### 10.2 `CSceneMgr:EnterScene` → `CScene:EnterPlayer`

```lua
function CSceneMgr:EnterScene(oPlayer, iScene, mInfo)
    -- 若玩家原来在某个场景，先离开
    if oNowScene then oNowScene:LeavePlayer(oPlayer, ...) end
    -- 进入新场景
    oNewScene:EnterPlayer(oPlayer, mInfo.pos, iFromSceneId)
end
```

`CScene:EnterPlayer`（位于 `service/world/sceneobj.lua`）：

```lua
function CScene:EnterPlayer(oPlayer, mPos, ...)
    -- 1. 记录玩家当前场景/坐标到 ActiveCtrl
    oPlayer.m_oActiveCtrl:SetNowSceneInfo({now_scene=..., now_pos=mPos})
    -- 2. 分配 EntityId
    local iEid = self:DispatchEntityId()
    self.m_mPlayers[pid] = iEid
    -- 3. 通知客户端切换场景 UI
    oPlayer:Send("GS2CShowScene", {scene_id, scene_name, map_id, x, y})
    -- 4. 通知远端 scene 服务，真正创建玩家实体
    interactive.Send(self.m_iRemoteAddr, "scene", "EnterPlayer",
        {scene_id, eid=iEid, data=oPlayer:PackSceneInfo(), pos=mPos, ...})
    -- 5. 触发事件 PLAYER_ENTER_SCENE
    self:TriggerEvent(...)
end
```

### 10.3 scene 服务侧 `CScene:EnterPlayer`

文件：`service/scene/sceneobj.lua`  第 221 行

```lua
function CScene:EnterPlayer(iPid, iEid, mPos, mInfo, iSpeed)
    -- 创建 CPlayerEntity 实体对象
    local obj = playerobj.NewPlayerEntity(iEid, iPid)
    obj:Init({scene_id, pos=mPos, speed, data=mInfo})

    -- 向客户端发送 GS2CEnterScene（包含 eid 和坐标）
    obj:Send("GS2CEnterScene", {scene_id, eid, pos_info={x,y,face_x,face_y,...}})

    -- 更新共享数据（用于跨服务器读取）
    obj:UpdateShareData(mPos)

    -- 向 world 服务广播事件（player_enter_scene）
    interactive.Send(".world", "scene", "RemoteEvent", {...})

    -- 加入 AOI 系统（CreateObject），触发与周围实体的 EnterAoi/LeaveAoi
    self:Enter(obj)
end
```

`self:Enter(obj)` 调用 `AoiAction("CreateObject", ...)` 将新玩家注册到 AOI 格中，AOI 系统会返回与该玩家互视的实体列表，触发：
- `oView:EnterAoi(o)` + `o:EnterAoi(oView)` — 双方互相发现
- 玩家收到视野内所有实体（其他玩家 + NPC）的 `GS2CEnterAoi` 消息

详细 AOI 同步流程见：[《场景进入+坐标同步》](./12-场景进入与坐标同步.md)

## 消息总结

从客户端视角，登录过程中收到的关键服务器消息：

| 消息 | 来源 | 说明 |
| ---- | ---- | ---- |
| `GS2CLoginError` | login | 登录失败（维护/封号等） |
| `GS2CLoginRole`  | world | 角色基础信息，标志登录成功 |
| `GS2CShowScene`  | world | 切换到对应场景的 UI |
| `GS2CEnterScene` | scene | 确认进入场景，附带自身 eid 和坐标 |
| `GS2CEnterAoi`   | scene | 视野内每个实体（玩家/NPC/宝箱）的信息 |
