# 注册与角色创建流程

> 说明"注册"在本项目中的含义：游戏本身没有独立的账号注册，账号由第三方 SDK（渠道平台）提供。本项目的"注册"等价于**首次创建角色**。
>
> 对应源码主要集中在：`service/loginverify/` 和 `service/login/CConnection.lua`。

## 1. 整体说明——账号体系

```
外部 SDK（渠道平台）
    ↓ 颁发 platform_token
客户端
    ↓ C2BSVerifyAccount（向 BS 发送 token）
BS → loginverify 服务
    ↓ 向 SDK 平台 HTTP 验证 token
    ↓ 验证通过后生成内部 session token
    ↓ 返回 server_info（服务器列表）+ role_list（已有角色列表）
客户端选择服务器并连接 GS
    ↓ C2GSLoginAccount（携带内部 token）
GS login 服务 → loginverify 服务 解析 token → 返回 account/channel
    ↓ 查询该账号在本服的角色列表（GS2CLoginAccount）
若角色列表为空 → 客户端显示创建角色界面
    ↓ C2GSCreateRole
角色创建完成 → GS2CCreateRole
客户端发起 C2GSLoginRole 正式进入游戏
```

- **无独立注册接口**：账号由外部 SDK 托管（channel = 0 时为调试/本地账号，直接用 account 字符串）。
- `iFirstRegister` 字段（由 `datacenter` 返回）标记该账号是否首次在任意服务器出现，供数据埋点使用。

## 2. 账号验证(CS 侧 loginverify 服务)

文件：`service/loginverify/verifymgr.lua`

### 2.1 SDK Token 验证

```lua
function CVerifyMgr:ClientVerifyAccount(sToken, iChannel, sDeviceId, ...)
    if iChannel ~= 0 then
        -- 向第三方 SDK 平台发送 HTTP POST 验证请求
        self:SdkVerify(sToken, iChannel, sDeviceId, function(errcode, mAccount)
            self:SdkVerifyEnd(errcode, mAccount, ...)
        end)
    else
        -- channel=0：调试/本地模式，跳过 SDK 验证，直接用 uuid 作为 account
        self:SdkVerifyEnd(0, {p=0, uid=sChannelUuid}, ...)
    end
end
```

### 2.2 验证通过后的处理

```lua
function CVerifyMgr:SdkVerifyEnd(errcode, mAccount, ...)
    local sAccount = mAccount.uid   -- SDK 返回的唯一账号 ID
    -- 生成内部 session token（格式：timestamp_serviceKey，有效期 30 分钟）
    mResult.token = self:GenerateMyToken(sAccount, iChannel, sCpsChannel, iPlatform, mOther)

    -- 获取服务器列表（从 serversetter 服务）
    self:RequestServerInfo(iChannel, iPlatform, sCpsChannel, mOther, function(...)
        -- 获取该账号在各服务器已有的角色列表（从 datacenter）
        self:RequestRoleInfos(sAccount, iChannel, iPlatform, lServerList, sDeviceId, function(...)
            -- 汇总后返回给客户端
            mResult.role_list     = mRoles
            mResult.first_register = iFirstRegister   -- 1=该账号首次注册
            endfunc({errcode=0, info=mResult})
        end)
    end)
end
```

`first_register > 0` 时触发 `RegisterAccount_1` 数据埋点日志。

## 3. 账号登录(GS 侧 login 服务返回角色列表)

客户端连接 GS 后发送 `C2GSLoginAccount`，携带 loginverify 颁发的内部 token。

文件：`service/login/CConnection.lua`

### 3.1 `CConnection:LoginAccount`

```lua
function CConnection:LoginAccount(mData)
    -- 校验 APP 版本
    -- 状态检查：必须是 no_account 状态
    -- 保存设备信息（mac/device/platform/imei/os/client_ver/udid）

    if sToken and sToken ~= "" then
        -- 有 token：到 loginverify 服务解析 account/channel 信息
        self:InitAccountInfo(sToken, function(errcode)
            oConn:_LoginAccount1(errcode)
        end)
    else
        -- 无 token（调试模式）：直接用 account 字段
        self:_LoginAccount1(0)
    end
end
```

### 3.2 `_LoginAccount2` → 查询本服角色列表

```lua
function CConnection:_LoginAccount2()
    gamedb.LoadDb("login", "common", "DbOperate", {
        module = "playerdb",
        cmd    = "GetPlayerListByAccount",
        cond   = {account=sAccount, channel=iChannel, platform=iPlatform},
    }, function(mRecord, mData)
        oConn:_LoginAccount3(mRecord, mData)
    end)
end
```

### 3.3 `_LoginAccount3` → 向客户端返回角色列表

```lua
function CConnection:_LoginAccount3(mRecord, mData)
    self.m_oStatus:Set(gamedefines.LOGIN_CONNECTION_STATUS.login_account)

    local lRet = {}
    for _, v in ipairs(mData.data) do
        if not v.deleted then
            table.insert(lRet, {
                pid        = v.pid,
                grade      = mBase.grade,
                name       = v.name,
                model_info = {...},
                school     = mBase.school,
            })
        end
    end
    -- 发送角色列表给客户端；客户端若列表为空则展示创建角色界面
    self:Send("GS2CLoginAccount", {
        account   = mData.account,
        channel   = mData.channel,
        role_list = lRet,
    })
end
```

## 4. 创建角色流程

客户端在角色选择界面点击创建，发送 `C2GSCreateRole`。

### 4.1 `CConnection:CreateRole` — 服务器选择校验

```lua
-- @param mData  table  {server_key:string, role_type:int, name:string, school:int}
function CConnection:CreateRole(mData)
    local sServerKey = mData.server_key or get_server_key()
    -- 校验目标服务器是否为本服或已连接的关联服
    if sServerKey == get_server_key() or oGateMgr:IsLinkedServer(sServerKey) then
        self:_CreateRole2(0, mData)
    end
end
```

### 4.2 `_CreateRole2` / `_CreateRole3` — 角色数量限制检查

```lua
function CConnection:_CreateRole3(mCnt, mData)
    -- mCnt: {serverTag: roleCount, ...}  各服已有角色数

    -- 同一服务器角色上限为 3
    if mCnt[sServerTag] and mCnt[sServerTag] >= 3 then
        self:Send("GS2CLoginError", {errcode = gamedefines.ERRCODE.role_max_limit})
        return
    end

    -- bFirstRole: 该账号在所有服务器均无角色，为真正首次注册
    local bFirstRole = iTot <= 0
    self:TrueCreateRole(mData, bFirstRole)
end
```

### 4.3 `CConnection:TrueCreateRole` — 核心创建逻辑

```lua
-- @param mData      table  {server_key, role_type, name, school}
-- @param bFirstRole bool   是否为账号的第一个角色（用于注册日志）
function CConnection:TrueCreateRole(mData, bFirstRole)
    -- 状态检查：必须是 login_account
    self.m_oStatus:Set(gamedefines.LOGIN_CONNECTION_STATUS.in_create_role)

    -- 校验 roletype 和 school 合法性（查 daobiao/roletype 配置表）
    -- Step 1: 检查名字唯一性（写入 namecounter 表，失败则 name_exist 错误）
    gamedb.LoadDb("login", "common", "DbOperate", {
        module = "namecounter",
        cmd    = "InsertNewNameCounter",
        data   = {name = sName},
    }, function(mRecord, mData)
        oConn:_TrueCreateRole1(...)
    end)
end
```

### 4.4 `_TrueCreateRole1` — 向 datacenter 申请 pid

名字占位成功后，向 CS 侧 `.datacenter` 服务请求创建角色，获取全局唯一的 `pid`：

```lua
function CConnection:_TrueCreateRole1(mRecord, mData, iRoleType, sName, iSchool, sServerTag, bFirstRole)
    if not mData.success then
        -- 名字已存在
        self.m_oStatus:Set(gamedefines.LOGIN_CONNECTION_STATUS.login_account)
        self:Send("GS2CLoginError", {errcode = gamedefines.ERRCODE.name_exist})
    else
        router.Request("cs", ".datacenter", "common", "TryCreateRole", {
            server      = get_server_tag(),
            born_server = sServerTag,
            account     = self:GetAccount(),
            channel     = self:GetChannel(),
            name        = sName,
            school      = iSchool,
            icon        = mInfo.shape,
        }, function(mRecord, mData)
            oConn:_TrueCreateRole2(mData, ...)
        end)
    end
end
```

失败回滚：若任意步骤后续连接断开，需回滚 `namecounter` 和 `datacenter` 中的状态（见代码中的 revert 逻辑）。

### 4.5 `_TrueCreateRole2` — 写入 DB 并返回客户端

```lua
function CConnection:_TrueCreateRole2(mData, iRoleType, sName, iSchool, sServerTag, bFirstRole)
    local id = mData.id   -- datacenter 分配的全局唯一 pid

    -- 构建初始角色数据
    local mCreateInfo = self:GetCreateInfo(sServerTag, sAccount, iChannel, iPlatform, id, iSchool, mInfo)
    mCreateInfo.name = sName

    -- 写入 game.player 表（playerdb 模块）
    gamedb.SaveDb("login", "common", "DbOperate", {
        module = "playerdb",
        cmd    = "CreatePlayer",
        data   = {data = mCreateInfo},
    })

    -- 写入 game.offline 表（离线数据初始化）
    gamedb.SaveDb("login", "common", "DbOperate", {
        module = "offlinedb",
        cmd    = "CreateOffline",
        data   = {data = {pid = id}},
    })

    self.m_oStatus:Set(gamedefines.LOGIN_CONNECTION_STATUS.login_account)   -- 恢复状态

    -- 首次注册：写注册日志和埋点
    if bFirstRole then
        self:LogRegisterAccount()   -- 触发 RegisterAccount / RegisterAccount_2 埋点
    end

    -- 数据分析埋点
    analy.log_data("CreatRole", {...})

    -- 通知客户端角色创建成功
    self:Send("GS2CCreateRole", {
        account     = sAccount,
        channel     = iChannel,
        create_time = mCreateInfo.create_time,
        role = {
            pid        = id,
            grade      = mCreateInfo.base_info.grade,   -- 初始为 0
            name       = mCreateInfo.name,
            school     = iSchool,
            model_info = {...},
        }
    })
end
```

客户端收到 `GS2CCreateRole` 后，直接发起 `C2GSLoginRole` 进入游戏（见登录流程文档）。

## 5. GetCreateInfo——角色初始数据结构

文件：`service/login/CConnection.lua`  第 706 行

```lua
function CConnection:GetCreateInfo(sServerTag, sAccount, iChannel, iFakePlatform, iPid, iSchool, mExtend)
    return {
        pid         = iPid,
        account     = sAccount,
        channel     = iChannel,
        platform    = iFakePlatform,
        name        = string.format("DEBUG%d", iPid),  -- 占位，后续由调用方覆盖
        create_time = get_time(),
        born_server = sServerTag,
        now_server  = get_server_tag(),
        deleted     = false,
        base_info   = {
            grade    = 0,              -- 初始等级 0
            sex      = mExtend.sex,
            school   = iSchool,        -- 职业/门派
            icon     = mExtend.shape,
            role_type = mExtend.roletype,
            model_info = {
                shape          = mExtend.shape,
                scale          = 0,
                color          = {0},
                mutate_texture = 0,
                weapon         = 0,
                adorn          = 0,
            },
        },
        -- 初始位置：map 1001，坐标 (100, 100)
        active_info = {
            map_id = 1001,
            pos    = {x=100, y=100, z=0, face_x=0, face_y=0, face_z=0},
        },
    }
end
```

**`active_info.map_id = 1001` + `pos = {100, 100}`** 即为新角色第一次进入游戏时 `EnterDurableScene` 读取的初始地图和坐标。

## 6. 账号数据写入数据库时机

> **核心结论：账号在首次通过 SDK 验证时就已写入数据库，与是否创建角色无关。**

### 6.1 写入时机总览

```
时机1 ─ SDK Token 验证通过（首次登录）
    verifymgr:RequestRoleInfos
        → datacenter:GetRoleList（logiccmd/common.lua）
            → datacenter:CheckFirstRegister
                ├─ 写 register 表       {account, channel, platform}      CS-MongoDB
                └─ 写 device_register 表 {device_id}                       CS-MongoDB

时机2 ─ 创建角色（_TrueCreateRole2）
    → datacenter:TryCreateRole（routercmd/common.lua）
        → datacenterobj:_TryCreateRole2
            └─ 写 roleinfo 表          {pid, account, name, school, ...}  CS-MongoDB
    → gamedb.SaveDb "CreatePlayer"
        └─ 写 game.player 表           完整 playerdb 记录                   GS-MongoDB
    → gamedb.SaveDb "CreateOffline"
        └─ 写 game.offline 表          {pid}                               GS-MongoDB
```

---

### 6.2 时机1：`register` 表写入

文件：`service/datacenter/datacenterobj.lua` — `CheckFirstRegister`

```lua
function CDataCenter:CheckFirstRegister(sAccount, lChannel, iPlatform, sDeviceId)
    -- 查 register 表：同一 (account, channel, platform) 是否已存在
    local m = self.m_oGameDb:Find("register", {
        account  = sAccount,
        channel  = {["$in"] = lChannel},
        platform = iPlatform,
    }, {account=true, channel=true, platform=true})

    if m:hasNext() then
        bFirstRegister = false             -- 已有记录，不是首次
    else
        -- 首次：向 register 表写入一条记录（每个 channel 一条）
        for _, iChannel in ipairs(lChannel) do
            self.m_oGameDb:Insert("register", {
                account  = sAccount,
                channel  = iChannel,
                platform = iPlatform,
            })
        end
        bFirstRegister = true
    end
    -- 同样逻辑写 device_register 表（以 device_id 为唯一键）
    ...
    return bFirstRegister, bDeviceFirstRegister
end
```

**调用路径**：
```
verifymgr:SdkVerifyEnd
  └→ OnGetServerList
       └→ RequestRoleInfos
            └→ datacenter [logiccmd] GetRoleList
                 ├─ CheckFirstRegister  ← 此处写 register / device_register
                 └─ GetRoleList        ← 读 roleinfo
```

`first_register=1` 会随着 `GS2CVerifyAccount` 的 `first_register` 字段透传给客户端，同时触发 `RegisterAccount_1` 埋点日志（`verifymgr:LogAccountInfo`）。

### 6.3 时机2：`roleinfo` 表写入

文件：`service/datacenter/datacenterobj.lua` — `_TryCreateRole2`

```lua
function CDataCenter:_TryCreateRole2(mRecord, mData, sServerTag, sBornServer, sAccount, iChannel, mInfo)
    local iPid = mData.id   -- idsupply 服务分配的自增 pid
    local mInsert = {
        server     = sBornServer,     -- 创建时的服务器
        now_server = sServerTag,      -- 当前服务器
        account    = sAccount,
        platform   = mInfo.platform,
        pid        = iPid,
        icon       = mInfo.icon,
        grade      = 0,
        school     = mInfo.school,
        name       = mInfo.name,
        channel    = iChannel,
        login_time = get_time(),
    }
    self.m_oGameDb:Insert("roleinfo", mInsert)
    return iPid
end
```

`roleinfo` 表是 CS 侧跨服角色全局索引，`GetRoleList` 从这里读取角色列表返回给客户端。

### 6.5 各表职责对比

| 表名 | 所在服务 | 写入时机 | 主要字段 | 用途 |
| --- | --- | --- | --- | --- |
| `register` | CS-datacenter | 首次 SDK 登录 | account, channel, platform | 判断是否首次注册（埋点） |
| `device_register` | CS-datacenter | 首次 SDK 登录 | device_id | 按设备判断首次注册 |
| `roleinfo` | CS-datacenter | 创建角色 | pid, account, name, grade, school | 跨服角色全局索引，供GetRoleList使用 |
| `game.player` | GS-gamedb | 创建角色 | 全量playerdb记录 | GS侧角色数据，LoginRole时加载 |
| `game.offline` | GS-gamedb | 创建角色 | pid | 离线邮件/奖励等离线数据 |

## 7. 关键消息总结

| 阶段 | 方向 | 消息 | 说明 |
| ---- | ---- | ---- | ---- |
| BS 验证 | C→BS | `C2BSVerifyAccount` | 携带 SDK token |
| BS 验证 | BS→C | `GS2CVerifyAccount` | 返回内部 token + 服务器列表 + 已有角色 |
| GS 账号登录 | C→GS | `C2GSLoginAccount` | 携带内部 token |
| GS 账号登录 | GS→C | `GS2CLoginAccount` | 返回本服角色列表（空列表→显示创建角色） |
| 创建角色 | C→GS | `C2GSCreateRole` | `{server_key, role_type, name, school}` |
| 创建角色 | GS→C | `GS2CLoginError` | 失败时：name_exist / role_max_limit 等 |
| 创建角色 | GS→C | `GS2CCreateRole`  | 成功时：返回新角色信息 |
| 进入游戏 | C→GS | `C2GSLoginRole`   | 创建成功后立即发起，进入正式登录流程 |

> 后续 `C2GSLoginRole` 的完整流程见：[《登录流程(完整版)》](./11-登录流程(完整版).md)
