# 大话许仙服务端架构说明

> 本文档面向新加入的开发者，帮助快速理解服务端整体架构、服务职责和开发流程。

---

## 一、框架概述

本项目基于 **Skynet** 框架开发。Skynet 是一个基于 Actor 模型的游戏服务器框架：

- 每个**服务（Service）**是一个独立的 Lua 虚拟机，运行在独立的协程中
- 服务间通过**消息传递**通信，不共享内存（天然无锁）
- 支持数万个并发服务，每个服务内部是单线程的
- 底层由 C 实现，Lua 层编写业务逻辑

**推荐先阅读**：[Skynet Wiki](https://github.com/cloudwu/skynet/wiki)

## 二、服务器进程架构

本项目运行时由多个独立进程组成：

```
         客户端 (Client)
              |
              | TCP 连接
              v
    ┌─────────────────┐
    │   GS (Game      │  ← 游戏主逻辑，处理玩家请求
    │   Server)       │    端口：7011, 7012 等
    └────────┬────────┘
             │ 服务器间通信（router_s）
             v
    ┌─────────────────┐
    │   CS (Center    │  ← 中心服务器，跨服逻辑
    │   Server)       │    端口：10010~10013
    └────────┬────────┘
             │
             v
    ┌─────────────────┐
    │   BS (Backend   │  ← 后台管理，运营工具
    │   Server)       │    端口：20001+
    └─────────────────┘

    ┌─────────────────┐
    │   KS (Keep      │  ← 存档/保活服务（独立进程）
    │   Server)       │
    └─────────────────┘
```

### 各服务器职责

| 服务器 | 职责 |
|--------|------|
| **GS** | 玩家直连，处理游戏核心逻辑（登录、场景、战斗、聊天等） |
| **CS** | 跨服全局逻辑（跨服数据、登录验证、全局排名、支付等） |
| **BS** | 后台运营工具（GM命令、数据查询、充值审核等） |
| **KS** | 数据存档与保活（定期落地关键数据） |

## 三、GS 服务启动流程

`gs_launcher.lua` 按顺序启动以下服务：

```
gs_launcher
    │
    ├── debug_console   # Skynet 调试控制台（telnet接入）
    ├── res             # 资源/配置文件加载服务
    ├── rt_monitor      # 实时性能监控
    ├── mem_monitor     # 内存监控
    ├── mem_rt_monitor  # 实时内存监控
    ├── dictator        # 协调服务（等待所有服务启动完成后开放服务器）
    ├── router_c        # 客户端路由（接受玩家TCP连接）
    ├── webrouter       # Web HTTP 路由（GM接口、健康检查等）
    ├── gamedb × N      # 数据库服务（N个实例，并发读写MongoDB）
    ├── login           # 登录逻辑服务
    ├── logdb           # 日志写入服务
    ├── logstatistics   # 日志统计服务
    ├── broadcast       # 全服广播服务
    ├── clientupdate    # 客户端更新通知服务
    ├── logfile         # 文件日志服务
    ├── logmonitor      # 日志监控服务
    ├── world           # 世界服务（全局游戏状态）
    ├── testclient      # 测试客户端（仅开发环境）
    ├── merger          # 服务合并工具
    └── chat            # 聊天服务
```

**关键流程**：所有服务启动完毕后，launcher 发送 `AllServiceBooted` 给 `dictator`，由 `dictator` 负责开放玩家连接入口。

## 四、CS 服务启动流程

`cs_launcher.lua` 按顺序启动以下服务：

```
cs_launcher
    │
    ├── debug_console
    ├── res
    ├── rt_monitor / mem_monitor / dictator
    ├── router_s × N    # 服务器间路由（接受来自 GS 的连接）
    ├── router_c        # 客户端路由
    ├── webrouter
    ├── gamedb × N      # 数据库服务
    ├── logdb
    ├── serversetter    # 服务器参数设置服务
    ├── idsupply        # ID生成服务（全局唯一ID）
    ├── loginverify × N # 登录验证服务
    ├── datacenter      # 数据中心（跨服数据共享）
    ├── logfile / logmonitor
    ├── redeemcode      # 兑换码服务
    ├── qrcode × N      # 二维码服务
    ├── pay × N         # 支付服务
    ├── backendinfo     # 后台信息服务
    └── merger
```

## 五、核心公共库说明

### `lualib/base/` — 框架底层库

| 文件 | 用途 |
|------|------|
| `preload.lua` | **每个服务启动时自动执行**，注入全局变量（MY_ADDR, MY_SERVER_KEY 等）和初始化基础模块 |
| `interactive.lua` | **服务间通信核心**，封装 Send/Request/Response，所有服务间调用都通过它 |
| `servicesave.lua` | 数据自动保存，注册保存任务后定时触发回调写数据库 |
| `servicetimer.lua` | 服务内定时器，支持 AddCallback/DelCallback |
| `net.lua` | TCP 网络连接封装（接受客户端连接、断开处理等） |
| `router.lua` | 路由逻辑封装（消息路由到玩家所在服务） |
| `mongoop.lua` | MongoDB 操作封装（增删改查） |
| `baseobj.lua` | OOP 基类，提供 New/Release/继承 等基础方法 |
| `tableop.lua` | table 工具函数（深拷贝、合并、序列化等） |
| `stringop.lua` | string 工具函数（split、trim 等） |
| `timeop.lua` | 时间工具（获取当前时间、时间格式化、判断是否同一天等） |
| `extend.lua` | Lua 标准库扩展（math/table/string 扩展） |
| `reload.lua` | 热重载支持，线上修复 bug 时不重启服务 |
| `idpool.lua` | ID 池管理（本地唯一ID生成） |
| `tbpool.lua` | table 对象池，减少 GC 压力 |
| `memcmp.lua` | 内存比较工具，用于检测数据变化 |

### `lualib/public/` — 业务层公共库

| 文件 | 用途 |
|------|------|
| `record.lua` | **日志系统**，提供 error/info/warning/debug 和数据库日志接口，所有服务都应使用此模块 |
| `serverdefines.lua` | **服务器配置常量**，端口号、服务实例数量等，在 `preload.lua` 中自动加载 |
| `gamedefines.lua` | 游戏业务常量（枚举值、游戏参数等） |
| `gamedb.lua` | gamedb 服务的 RPC 封装，供其他服务调用数据库操作 |
| `serverinfo.lua` | 服务器信息管理（在线人数、服务器状态等） |
| `serverdesc.lua` | 服务器描述信息（服务器列表、名称等） |
| `resfile.lua` | 资源文件加载（导表数据访问） |
| `util.lua` | 通用工具函数 |
| `analylog.lua` | 数据分析日志上报 |
| `httpuse.lua` | HTTP 请求工具（调用第三方接口） |

## 六、消息通信流程示例

### 示例 1：GS 服务 A 向服务 B 发送单向消息

```lua
-- 在 service/A/init.lua 中
local interactive = require "base.interactive"

-- 告知 broadcast 服务广播一条消息（不需要等待结果）
interactive.Send(".broadcast", "common", "PushMsg", {
    msg = "服务器将在5分钟后维护"
})
```

### 示例 2：服务 A 向 gamedb 请求数据（带回调）

```lua
local interactive = require "base.interactive"

interactive.Request(".gamedb", "common", "LoadPlayer", {uid = 10001}, function(mRecord, mData)
    local player_data = mData.data
    -- 处理玩家数据...
end)
```

### 示例 3：服务 B 处理并响应请求

```lua
-- 在 moduleLogic.Invoke 中处理 "common" 模块的 "LoadPlayer" 命令
function ModuleLogic:Invoke(sModule, sCmd, mRecord, mData)
    if sModule == "common" and sCmd == "LoadPlayer" then
        local uid = mData.uid
        local data = self:_LoadFromDB(uid)
        interactive.Response(mRecord.source, mRecord.session, {data = data})
    end
end
```

## 七、新建服务完整示例

以新增一个「邮件服务」为例：

### 步骤 1：创建 `service/mail/init.lua`

```lua
-------------------------------------------------------------------
-- @file    init.lua
-- @service mail
-- @brief   游戏内邮件系统服务
-- @server  gs
--
-- 详细说明：
--   负责处理玩家邮件的收发、存储和删除。
--   玩家登录后由 login 服务通知 mail 服务加载邮件列表。
--   依赖 gamedb 服务进行数据持久化。
--
-- 依赖服务：
--   - .gamedb  : 邮件数据读写
--   - .login   : 玩家登录事件
-------------------------------------------------------------------
local skynet = require "skynet"
local interactive = require "base.interactive"
local record = require "public.record"

-- 加载业务逻辑模块
local CMailLogic = require "mail.logic"

skynet.start(function()
    record.info("mail start")

    skynet.register(".mail")

    local oLogic = CMailLogic:New()
    oLogic:Init()

    interactive.Dispatch(oLogic)

    record.info("mail ready")
end)
```

### 步骤 2：在 `service/gs_launcher.lua` 中注册

在 `skynet.start()` 函数体中，找到合适的位置添加：
```lua
skynet.newservice("mail")
```

### 步骤 3：创建 `service/mail/logic.lua`（业务逻辑）

```lua
-------------------------------------------------------------------
-- @file    logic.lua
-- @brief   邮件服务业务逻辑处理
-------------------------------------------------------------------
local interactive = require "base.interactive"
local record = require "public.record"

---@class CMailLogic 邮件服务逻辑类
local CMailLogic = {}
CMailLogic.__index = CMailLogic

--- 创建新实例
---@return CMailLogic
function CMailLogic:New()
    return setmetatable({}, self)
end

--- 初始化
function CMailLogic:Init()
    record.info("mail logic init")
end

--- 消息分发入口（由 interactive.Dispatch 调用）
---@param sModule string 模块名
---@param sCmd string 命令名
---@param mRecord table 消息记录（含 source, session 等）
---@param mData table 消息数据
function CMailLogic:Invoke(sModule, sCmd, mRecord, mData)
    if sModule == "common" then
        if sCmd == "SendMail" then
            self:_OnSendMail(mRecord, mData)
        elseif sCmd == "GetMailList" then
            self:_OnGetMailList(mRecord, mData)
        end
    end
end

--- 处理发送邮件请求
---@param mRecord table 消息记录
---@param mData table 包含 uid(integer), title(string), content(string)

    record.info("send mail to uid:%s", tostring(mData.uid))
end

--- 处理获取邮件列表请求
---@param mRecord table 消息记录
---@param mData table 包含 uid(integer)
```

## 八、开发常见问题

### Q: 怎么知道某个消息是发给哪个服务的？
全局搜索命令名，如搜索 `"AllServiceBooted"` 可以找到所有发送方和处理方。

### Q: 服务名前面的 `.` 是什么意思？
`.服务名` 是 Skynet 的命名服务格式，表示通过名字查找服务地址。服务启动时调用 `skynet.register(".服务名")` 注册。

### Q: gamedb 有多个实例，怎么知道数据存在哪个实例？
通常按 uid 取模分配：`".gamedb_" .. (uid % GAMEDB_SERVICE_COUNT + 1)`，具体逻辑看 `lualib/public/gamedb.lua`。

### Q: 如何热重载修改后的代码？
通过 telnet 连接到 debug_console 端口，执行 reload 命令。具体见 `lualib/base/reload.lua`。

### Q: 日志文件在哪里？
`./log/{server_key}/` 目录下，如 `./log/dev_gs10001/`。

### Q: 怎么本地启动服务？
```bash
# 编译
make

# 启动 GS
./gs_run.sh

# 启动 CS
./cs_run.sh

# 启动所有
./all_start.sh
```
